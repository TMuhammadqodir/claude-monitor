# Claude Monitor

[English](README.md) · [O‘zbekcha](README.uz.md) · **Русский**

Одна панель для Claude Code на нескольких компьютерах: сколько токенов использовал каждый, сколько это стоило
бы по ценам API, сессии, модели, 5-часовой и недельный лимиты подписки с долей каждого компьютера, ошибки и
живая лента. Из панели можно ограничить компьютер или остановить на нём Claude.

Ничего устанавливать не нужно: достаточно Node.js 22.13 или новее (используется встроенный `node:sqlite`).

## Как это работает

```
 Компьютер 1 ─┐  OpenTelemetry Claude Code (каждый запрос: модель, токены, цена, аккаунт)
 Компьютер 2 ─┼──────────────►  server.mjs  ──►  data/monitor.db  ──►  панель (браузер)
 ...         ─┘  agent.mjs: старые логи, точные проценты лимитов, проверка лимитов (хуки)
```

- **Живые данные.** В Claude Code встроена телеметрия
  ([monitoring-usage](https://code.claude.com/docs/en/monitoring-usage)). После каждого запроса к API он
  отправляет на сервер модель, токены, цену (`cost_usd`) и аккаунт. Компьютер узнаётся по своему токену (`cm_...`).
- **История.** Claude Code пишет каждую сессию в `~/.claude/projects/**/*.jsonl`. Агент читает оттуда только
  числа, поэтому виден и расход до включения телеметрии. Запрос, пришедший обоими путями, считается один раз
  (по его `req_...`).
- **Что никогда не отправляется.** Промпты, ответы, код и файлы: Claude Code сам их скрывает (`<REDACTED>`), а
  агент читает только числа и имя папки проекта.

## Запуск

Запустите сервер там, куда дотянутся все компьютеры: на компьютере в домашней или офисной сети (для разных
мест удобен Tailscale) или на VPS.

```sh
node server.mjs                        # порт 4318, данные в ./data/monitor.db
PORT=8080 DATA=/srv/monitor.db node server.mjs
```

В Windows PowerShell: `$env:PORT=8080; node server.mjs`.

1. Откройте `http://<server>:4318` и задайте пароль панели. Страница спросит **код настройки**, который сервер
   вывел при запуске (`Setup code: ...`), — так никто другой в сети не займёт панель раньше вас.
2. Нажмите **«Добавить компьютер»** и дайте имя. Токен показывается один раз.
3. На этом компьютере выполните две команды, которые покажет панель:

   ```sh
   curl -o agent.mjs http://<server>:4318/agent.mjs
   node agent.mjs setup --server http://<server>:4318 --token cm_...
   ```

4. Перезапустите Claude Code. После первого запроса компьютер станет «Работает».

`setup` записывает настройки телеметрии в раздел `env` файла `~/.claude/settings.json` (прежний сохраняется
как `settings.json.bak`), добавляет свои хуки (чужие не трогает), копирует себя в `~/.claude/claude-monitor/`
и отправляет прошлый расход. `.claude/settings.json` проекта для этого не подходит: Claude Code берёт
телеметрию только из пользовательских настроек. Отменить: `node agent.mjs remove`.

| Хук | Когда | Что делает |
|---|---|---|
| `UserPromptSubmit` → `gate` | перед каждым промптом | останавливает промпт, если компьютер остановлен или исчерпал лимит |
| `PreToolUse` → `guard` | перед каждым вызовом инструмента | та же проверка (ответ запоминается на 10 с): Claude останавливается и посреди ответа |
| `Stop` → `report` | в конце каждого ответа | отправляет точные проценты (не чаще раза в минуту) |
| `SessionStart` → `session` | при старте сессии | запоминает её модель и применяет правила компьютера |
| `PreModelSwitch` → `model` | перед переключением `/model` | отклоняет неразрешённую модель |
| `PostModelSwitch` → `switched` | после смены модели | запоминает новую модель сессии |

**Модели и effort.** В настройках компьютера на панели отметьте разрешённые семейства моделей (Fable, Opus,
Sonnet, Haiku) и выберите предел effort. Агент записывает их в пользовательские настройки Claude Code
(`availableModels` + `enforceAvailableModels`, `maxEffortLevel`): Claude Code сам отклоняет другие модели и
выполняет более высокий effort на пределе; хуки тоже проверяют, а если запрос всё же вышел за правила, панель
сообщит. Нужен Claude Code 2.1.251 или новее. Собственные мелкие помощники Claude Code (заголовок сессии,
веб-страницы) всё равно могут использовать Haiku.

Каждый хук занимает около 0,1 с, и ни один не останавливает работу, если сервер недоступен.

**Обновление агента.** С `setup --auto-update` агент обновляется сам (см. ниже). Вручную: скачайте новый `agent.mjs` и выполните
`node agent.mjs update` — сервер и токен берутся из настроек. Claude Code читает хуки при запуске, поэтому
затем перезапустите его.

### Без телеметрии (или вместе с ней)

```sh
node agent.mjs watch --server http://<server>:4318 --token cm_... --every 5
```

Читает логи каждые 5 минут и отправляет новое. Не в реальном времени, зато не требует настроек.

## Что в панели

| Вкладка | Что показывает |
|---|---|
| Обзор | Лимиты подписки по аккаунтам (кольца, время обновления, темп, кто сколько использовал); сегодня, неделя, месяц (с дня оплаты) и ценность подписки; расход по дням по компьютерам; компьютеры; модели; виды токенов; строки, коммиты и PR; карта часов; проекты; инструменты; ошибки |
| Токены | За выбранный период: входные, выходные, прочитанные из кэша и записанные в кэш токены по моделям, точные числа, запросы и цена API; то же по каждому компьютеру |
| Лимиты | Лимиты подписки; каждое 5-часовое окно за 7 дней по моделям и компьютерам; сегодня и вчера, эта и прошлая неделя, этот и прошлый месяц |
| Компьютеры | Статус, система, версия Claude Code, IP, расход; по клику — график за 30 дней, модели, сессии и настройки (имя, цвет, лимиты, остановка, ссылка для просмотра, новый токен, удаление) |
| Сессии | Каждый разговор Claude Code: компьютер, аккаунт, длительность, запросы, токены, цена, модели, проект |
| Живая лента | Каждый запрос к API по мере поступления |
| Настройки | Тариф, чья подписка, день оплаты, курс сума, часовой пояс, язык сообщений, Telegram, пароль, экспорт CSV |

Панель говорит на **узбекском, английском и русском** (меню в заголовке; по умолчанию язык браузера).
Собственные сообщения сервера — уведомления, Telegram, причина остановки промпта — на **языке сообщений** из
настроек. Агент говорит на языке компьютера; другой выбирает `CLAUDE_MONITOR_LANG=uz|en|ru`.

**Статус компьютера.** «Работает»: запрос за последние 3 минуты. «На связи»: данные за 10 минут. «Работал
сегодня»: за 24 часа. «Не на связи»: дольше. «Ещё не подключён»: ничего не приходило.

## Точные проценты (как /usage в Claude Code)

Один раз на компьютере, где выполнен вход в аккаунт:

```sh
node agent.mjs usage --server http://<server>:4318 --token cm_...
```

Команда выводит проценты 5-часовой сессии и недели и отправляет их на панель; дальше их присылают хуки. Агент
читает ключ входа Claude Code на этом компьютере и отправляет его только в Anthropic; сервер получает только
проценты. Чей это аккаунт, сообщает профиль Anthropic, поэтому компьютер с setup-токеном другого аккаунта
(`CLAUDE_CODE_OAUTH_TOKEN`) отправляет проценты нужному аккаунту.

**Кто сколько использовал.** Каждый лимит делится между компьютерами, использовавшими аккаунт, по их расходу
за период (отсчитанный назад от времени обновления, которое даёт Anthropic): «5 часов 41%: Ноутбук 30%,
Офис-ПК 8%, другие места 3%».

- **Другие места (оценка)** — claude.ai, телефон или компьютер без агента. Панель узнаёт по прошлым периодам,
  сколько стоит 1% (медиана последнего отчёта каждого периода), и относит сюда часть процента, которую не
  объясняет расход компьютеров. В первые дни всё выглядит как расход компьютеров.
- **Месячный (оценка).** У Anthropic нет месячного лимита; месяц оплаты измеряется недельными лимитами —
  столько, сколько в нём недель.
- **Темп.** Под кольцами 5 часов и недели: в нынешнем темпе — когда закончится лимит (если раньше обновления).

**Один компьютер, несколько аккаунтов.** Claude Code отправляет аккаунт каждого запроса (`user.account_uuid`,
email), и каждый запрос считается своему аккаунту. Если друг на одном компьютере переключается между вашим и
своим аккаунтом, к вашим процентам добавится только то, что сделано на вашем. История из старых логов без
аккаунта считается последнему аккаунту компьютера.

## Лимиты и остановка

В окне компьютера, раздел **Лимиты**:

- **В долларах (цены API):** дневной, 5-часовое окно, недельный, месячный.
- **В процентах подписки:** «от 5-часовой сессии 20%», «от недельного 15%» — доля компьютера в проценте
  Anthropic. Нужны точные проценты; без них показывает 0% и ничего не останавливает.
- **Какой аккаунт считают лимиты:** если компьютер использует несколько аккаунтов, лимиты считают один, и
  остановка действует только пока используется он.
- **Останавливать промпты при исчерпании лимита.** Без отметки приходят только уведомления (на 80% и 100%,
  раз за период).

**Остановить Claude.** «⏸ Остановить Claude» сразу останавливает Claude на этом компьютере до «▶ Продолжить»:
новый промпт не выполняется, а текущий ответ заканчивается на следующем вызове инструмента. «Отключить
наблюдение» — другое: сервер лишь перестаёт принимать данные этого компьютера, Claude Code продолжает работать.

Проверки работают там, где установлен агент, пока сервер доступен; владелец компьютера может убрать хук из
своих настроек. Это контроль для своих компьютеров и доверенных людей.

## Ссылка для просмотра

«🔗 Ссылка для просмотра» в окне компьютера даёт страницу, которая открывается без пароля и показывает только
расход этого компьютера, его лимиты и долю в лимитах аккаунта (с итогом по аккаунту). Дайте её тому, кто
пользуется компьютером. «Новая ссылка» заменяет её, «Отключить ссылку» закрывает.

## Как считаются числа

- **Цены — цены API.** Подписка Pro или Max не оплачивается за токены; панель показывает, сколько та же работа
  стоила бы через API. «Ценность подписки ×3.3» — подписка за $200 сделала в этом месяце работы на $660. Если
  отслеживается несколько аккаунтов, считается только аккаунт владельца (Настройки → «Чья это подписка»;
  иначе самый активный). Цену в телеметрии считает сам Claude Code; история оценивается по `src/pricing.mjs`.
- **Найти компьютеры, войдя в аккаунт, нельзя:** у Anthropic нет открытого API для устройств подписки или их
  расхода, поэтому на каждом компьютере один раз выполняется `setup`.
- **5-часовые окна.** Запросы одного аккаунта делят окно, с какого бы компьютера они ни шли. Без точных
  процентов опорой служит расход окна на момент последней 429 (лимит достигнут).
- **Дни** считаются в часовом поясе из настроек, так что сервер за границей считает ваши дни.

## Чинит себя сам

- **Потерянный расход.** Когда сервер недоступен, компьютер спит или токен неверен, телеметрия теряет эти
  запросы. Раз в час агент (в фоне, не задерживая Claude Code) снова отправляет свежие логи: пробелы
  заполняются, ничего не считается дважды.
- **Обновление.** Только при настройке с `--auto-update`: каждые 6 часов агент сравнивает себя с `agent.mjs` на
  сервере и, если они различаются, берёт новый (после проверки синтаксиса) и даёт ему настроить хуки. По
  умолчанию выключено, потому что запускает код сервера на компьютере, где лежит ключ Claude Code: включайте
  только для сервера, которому доверяете, через HTTPS или Tailscale.
- **Отклонённый токен.** После «Новый токен» компьютер, который всё ещё отправляет старый, появляется в
  уведомлениях панели; его Claude Code сообщает об этом раз в час, а `node agent.mjs status` показывает «Связь: ✗».

## Безопасность

- Пароль панели хранится через scrypt; cookie сессии подписана (`HttpOnly`, `SameSite=Strict`, по HTTPS —
  `Secure`) и хранится на сервере, поэтому «Выйти» завершает её везде. Новый пароль завершает все сессии и
  требует текущий. Больше 5 попыток в минуту с одного адреса не принимаются.
- Первый пароль может задать только тот, у кого есть код настройки из окна сервера.
- За прокси (Caddy, Nginx) запускайте с `TRUST_PROXY=1`, чтобы попытки считались по реальному адресу
  (последнему в `X-Forwarded-For`, его добавляет прокси). Без прокси не включайте. Если прокси не передаёт
  `X-Forwarded-Proto: https`, задайте `COOKIE_SECURE=1`.
- Gzip-тело распаковывается не больше чем до 100 МБ. Токены компьютеров хранятся только в виде хэшей.
  Телеметрия проверяется: стоимость и счётчики не бывают меньше нуля, тексты обрезаются до разумной длины.
- Токен компьютера говорит только за этот компьютер: он может отправлять проценты только тех аккаунтов, которые
  видны в его собственной телеметрии. О неизвестных токенах сообщается не больше 5 раз в день.
- Лимиты компьютеров держат хуки агента: владелец компьютера может их убрать, а пока сервер недоступен, ничего
  не останавливается. Они удерживают в лимитах честных пользователей, а не того, кто хочет их обойти.
- База (и `backups/`) хранит хэш пароля, секрет сессий и токен Telegram: оставьте папку данных только
  пользователю сервера (в Linux и macOS файлы сами делаются читаемыми только для него).
- Точные проценты берутся из недокументированного `api/oauth/usage` Anthropic: он может измениться.
- Через интернет ставьте сервер за HTTPS (например Caddy или Nginx), иначе токены и пароль идут открыто. В
  домашней сети или Tailscale достаточно HTTP.
- `node agent.mjs setup` берёт токен и из `CLAUDE_MONITOR_TOKEN`, чтобы он не оставался в истории оболочки.
- Старые записи удаляются: события инструментов через `EVENT_DAYS` (180) дней, просмотренные уведомления через
  90 дней. Запросы хранятся, если `KEEP_DAYS` не задаёт срок.

## Постоянная работа

- **Linux (systemd):** `/etc/systemd/system/claude-monitor.service`

  ```ini
  [Service]
  WorkingDirectory=/opt/claude-monitor
  ExecStart=/usr/bin/node server.mjs
  Environment=PORT=4318
  Restart=always

  [Install]
  WantedBy=multi-user.target
  ```

- **Windows:** один раз в PowerShell, открытом от администратора:

  ```powershell
  powershell -ExecutionPolicy Bypass -File scripts\autostart-windows.ps1
  ```

  Сервер запускается при включении без окна (даже до входа пользователя), после сбоя поднимается в течение
  минуты и открывает порт 4318 в брандмауэре. Его вывод (и код настройки) пишется в `data\server.log`. Сначала
  закройте сервер, запущенный вручную, иначе порт занят. Отменить: та же команда с `-Remove`.
- **Резервные копии:** всё лежит в одном файле, `data/monitor.db`. Сервер каждый день копирует его в
  `data/backups/` и хранит 14 дней. Восстановить: остановите сервер и положите копию на место `data/monitor.db`.

## Если что-то не так

- **Компьютер не подключается.** Выполните на нём `node agent.mjs status`: последняя строка («Связь») скажет,
  отвечает ли сервер и принимает ли токен. Адрес сервера не должен быть «localhost» (он работает только на
  самом сервере), а брандмауэр сервера должен пропускать порт 4318.
- **Ошибка 415.** `OTEL_EXPORTER_OTLP_PROTOCOL` должен быть `http/json`: сервер не принимает protobuf.
- **Что отправляет Claude Code?** Запустите сервер с `MONITOR_DUMP=dump.jsonl node server.mjs`: каждый пакет
  запишется в этот файл.
